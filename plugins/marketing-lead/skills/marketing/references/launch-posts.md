# Launch posts: patterns per channel

Read this when you write launch posts (Step 5 of `SKILL.md`). Every draft starts with "DRAFT: you publish" or "DRAFT: you send", so nobody mistakes it for something already out.

## Before writing: what you need

- What is new, in one sentence, in the user's words.
- Who it is for (the situation, from the plan or the starred questions).
- Where people get it: the link. Use `https://example.com` until the user gives the real one.
- Price and conditions, or "free" with its conditions.
- One piece of proof the user can show, or none.
- Any relationship to disclose.
- The channels, and the rules page of each one, read on the channel's own site.

If one of these is missing, write the draft anyway with `[TO CONFIRM: ...]` in its place.

## The parts of every launch post

1. **The change** for the reader: before and after, in plain words. ("Booking a service used to mean a phone call during work hours. Now it takes a minute online.")
2. **What it is**, in one sentence. No adjectives the user cannot prove.
3. **Who it is for.** Name the situation, not a demographic.
4. **One proof**, if the user has one they can show: a screenshot, a price list, a short demo, a real customer's words with their permission. Never a made-up one.
5. **Price or "free"**, with the conditions in the same sentence or the next.
6. **The one action** and the tagged link.
7. **The disclosure**, when there is a relationship to disclose, in the post itself.

Cut every word that does not do one of these jobs.

## Patterns by channel type

Adapt the length and tone to the channel. Keep the facts identical across versions.

### Short social post

```
DRAFT: you publish. [channel], [date]
[The change, one line.]
[What it is, one line.] For [who].
[Price / free + conditions.]
[One action]: [tagged link]
[Disclosure, if any]
```

### Longer post (a professional network, a blog, a newsletter)

```
DRAFT: you publish. [channel], [date]
Title: [the change, as a plain statement]

[Two or three sentences on the situation the reader is in.]
[What is new and how it changes that situation.]
[Who it is for, and who it is not for.]
[The proof the user can show, or nothing.]
[Price / free + conditions.]
[One action]: [tagged link]
[Disclosure, if any.]
[AI note, if a reader would ask how it was made.]
```

### Community post (a forum, a group, a subreddit-style board)

Each community sets its own rules on self-promotion. Before drafting, read the community's own rules and tell the user which rule allows the post, with the link and the date. If self-promotion is not allowed, do not write a disguised ad: suggest the user asks the moderators, or skips that community.

```
DRAFT: you publish, if the rules allow it. [community], rules read: [URL, date]
[What you built or changed and why, as a member: the problem you had.]
[What it does, plainly. What it does not do yet.]
[Price / free + conditions.]
[Link, if the rules allow links.]
[Clear statement that you made it.]
[A real question for the community, if you have one.]
```

### Launch platforms

Read the platform's launch guide first. Product Hunt's, for example, says "The only real rule here is that you cannot ask people directly to upvote your product." (https://www.producthunt.com/launch, checked 2026-10-21). Never ask for votes where the rules forbid it, and never arrange votes from accounts that exist only for that.

### Launch email (opted-in list only)

This is general information, not legal advice. Other countries have their own rules.

This skill's rule: send only to people who agreed to hear from the user. For US recipients, the FTC's CAN-SPAM guide (https://www.ftc.gov/business-guidance/resources/can-spam-act-compliance-guide-business, checked 2026-10-23) says, among other things:
- "The subject line must accurately reflect the content of the message."
- "Your message must include your valid physical postal address."
- "You must honor a recipient's opt-out request within 10 business days."

```
DRAFT: you send. Launch email, to: [opted-in list name]
Subject: [plain and accurate: what is new]
Preview line: [the change, one line]

Hi [first name, if the list has it],
[The change for the reader.]
[What it is, one sentence.]
[Why you are telling them: they asked to hear about it.]
[Price / free + conditions.]
[One action]: [tagged link]

[Name]
[Business name], [physical postal address]
[Unsubscribe link: one step, works without logging in]
```

## Questions people will ask

Draft answers to the three questions most likely to come up, using only the user's facts: usually price, who it is for, and what it does not do yet. Mark any answer you are unsure of as `[TO CONFIRM]`. The user replies in person; never post replies from other accounts.

## Launch-day order for the user

1. Check every `[TO CONFIRM]` item.
2. Open each tagged link to make sure it works.
3. Approve each draft (in the calendar's `approved_by` column).
4. Publish or send each one yourself, in the planned order.
5. Answer replies in person.
6. On the review date, read the numbers from the plan's Measure box.
